Access to private data 🔐 2. Exposure to untrusted content (web pages, issues, emails, files) 🌐 3. A way to communicate externally 📤 <br> <br> <ul> <li class="fragment">Remove one leg, and prompt injection loses most of its teeth.</li> <li class="fragment">Sandboxing can help protecting against injection <em>and</em> mistakes.</li> </ul> == <!-- .slide: data-state="standard 9" data-background-image="./media/pexels-ekaterina-bolovtsova-6077797.jpg" --> ## Licensing - Purely AI-generated output is likely not copyrightable (US and EU) - Open-source licences rely on copyright, so licensing purely AI-written code is shaky - Generated code may reproduce licensed code verbatim - Snippet scanners exist (e.g. SCANOSS), but tooling is immature - Vendor "public code" filters and indemnities shift liability, but don't guarantee clean code - Some open-source projects restrict or ban AI-generated contributions == <!-- .slide: data-state="standard 9" data-background-image="./media/pexels-ekaterina-bolovtsova-6077797.jpg" --> ## Exercise 2: Checking AI Client Settings (15 mins) === <!-- .slide: data-state="standard 6" data-background-image="./media/pexels-trungnguyenphotog-5104548.jpg" --> <!-- https://www.pexels.com/photo/young-man-jumping-on-green-hill-5104548/ --> # Practice == <!-- .slide: data-state="standard 9" data-background-image="./media/pexels-trungnguyenphotog-5104548.jpg" --> ## Good Practices 1. Before touching code, discuss the architecture with the AI — it's a good sparring partner 2. Ask it to review your plan and surface edge cases you haven't considered 3. Supply links to relevant documentation in your prompt 4. Write the agreed plan to a file — this becomes compact context for future sessions Note: - Also see tab "Prompt Engineering" == <!-- .slide: data-state="standard 9" data-background-image="./media/pexels-trungnguyenphotog-5104548.jpg" --> ## The Prompt Framework **Role + Context + Task + Constraints + References** <table style="width:100%; border-collapse:collapse; font-size: smaller;"> <tr> <td style="padding:0.4rem 0.8rem; color:blue; white-space:nowrap;"><strong>Role</strong></td> <td style="padding:0.4rem 0.8rem;">"You are helping an RSE writing a data analysis pipeline in Python…"</td> </tr> <tr> <td style="padding:0.4rem 0.8rem; color:blue; white-space:nowrap;"><strong>Context</strong></td> <td style="padding:0.4rem 0.8rem;">Hardware, data format, scale, existing codebase, language/version</td> </tr> <tr> <td style="padding:0.4rem 0.8rem; color:blue; white-space:nowrap;"><strong>Task</strong></td> <td style="padding:0.4rem 0.8rem;">Specific, measurable outcome — not "make it faster", but "reduce runtime below 30s on 10GB input"</td> </tr> <tr> <td style="padding:0.4rem 0.8rem; color:blue; white-space:nowrap;"><strong>Constraints</strong></td> <td style="padding:0.4rem 0.8rem;">Memory limits, coding conventions, libraries allowed, what must not change</td> </tr> <tr> <td style="padding:0.4rem 0.8rem; color:blue; white-space:nowrap;"><strong>References</strong></td> <td style="padding:0.4rem 0.8rem;">Package docs, similar code, API specs — especially for niche libraries</td> </tr> </table> Note: - The better models get, the less important the "Role" becomes == <!-- .slide: data-state="standard 9" data-background-image="./media/pexels-trungnguyenphotog-5104548.jpg" --> ## Prompt Engineering Tips <div style="font-size: smaller;"> - Start broad ➜ discuss ➜ refine ➜ add constraints before implementation - Ambiguity during <em>implementation</em> is dangerous — be precise about signatures, types, return values - Ask for <strong>options</strong>: "Give me three approaches and their trade-offs" - Ask for <strong>steps</strong>: "Walk me through this optimisation step by step" - Provide <strong>examples</strong>: "This R function does X — implement the equivalent in Python" - Explaining the problem clearly helps <em>you</em> understand it better too </div> Note: - Writing a good prompt _requires the same clarity as writing a good specification_. - If you can't write a good specification, you have not fully defined the problem yet. == <!-- .slide: data-state="standard 9" data-background-image="./media/pexels-trungnguyenphotog-5104548.jpg" --> ## Transparency about AI Record, where relevant: - purpose and research activity - tool, provider, model and access route - date or version information - data or context supplied - material generated, transformed or evaluated - human review and verification performed - limitations, uncertainty and unresolved concerns - how the use affected authorship, attribution or interpretation == <!-- .slide: data-state="standard 9" data-background-image="./media/pexels-trungnguyenphotog-5104548.jpg" --> ## Exercise 3: AI Declaration Tool (15 min) === <!-- .slide: data-state="standard 6" data-background-image="media/pexels-ekaterina-bolovtsova-6192336.jpg" --> <!-- https://www.pexels.com/photo/a-notebook-with-blank-pages-6192336/ --> # Wrap-Up == <!-- .slide: data-state="standard 9" data-background-image="media/pexels-ekaterina-bolovtsova-6192336.jpg" --> ## Key Takeaways -
